VXC Motors Session Inspector

Twelve AI agents run a BMW dealership for a day. Every word they send to the LLM passes through one proxy that logs it, checks it against five sensitive topics, and blocks the conversation when it has to. This page walks through how it was built, one lesson at a time, with the live visualization for each step.

Act 1 · One agent and a proxy

Start as small as possible: one agent with two tools. Then put a proxy between it and the LLM, and make the proxy remember everything.

Lesson 1

An agent calling OpenRouter

Topology map ↗
What it adds

An agent is a loop: send the conversation and a list of tools to the LLM, run whatever tool it asks for, append the result, repeat until it answers in plain text.

  • OpenAI-compatible client pointed at OpenRouter, free model nvidia/nemotron-3.5-super-vl:free.
  • Tools are JSON schemas; finish_reason=tool_calls keeps the loop going, stop ends it.
  • The agent holds the real API key. That is the problem the next lesson fixes.

Lesson 2

The same agent, through a proxy

Topology map ↗
What it adds

The agent changes one setting, its base URL, and sends a dummy key. The proxy swaps in the real key and forwards the request unchanged.

  • LLM_BASE_URL=http://127.0.0.1:8080/v1, LLM_API_KEY=dummy.
  • The proxy forwards whole, non-streamed messages, so it sees every complete request and answer. That is what makes inspection possible later.
  • Only the proxy reads OPENROUTER_API_KEY.

Lesson 3

Proxy logging

Sequence diagram ↗
What it adds

Every exchange is written to SQLite before the answer goes back: who asked, in which session, what was sent, what came back, how long it took and how many tokens it used.

  • logs/proxy.db, table calls; the key never reaches the database.
  • Agents label themselves with X-Agent-Id and X-Session-Id; the proxy logs and strips them.
  • proxy/view_log.py lists sessions and replays one turn by turn.

Lesson 3b

The LLM gateway: a shared budget

Seen in mission control ↓
What it adds

Before running many agents, the proxy gets budget rules that hold no matter how many agents call it at once.

  • At most 16 requests a minute across all agents, with backoff on 429.
  • The free model has 1,000 requests a day for the whole account; after that, a cheap paid fallback (z-ai/glm-5.3-flash) under a hard spend cap.
  • Every answer is cached by a hash of the request: GATEWAY_CACHE=record | replay | strict.

Lesson 5

Internal systems and the BMW portal

Data model ↗
What it adds

Agents need something real to work on. Six internal systems and BMW's external partner portal become 69 tools over two DuckDB databases, seeded with history from January 2026.

  • Internal: CRM, dealer management, workshop planner, parts, finance, email and chat. External: car and parts orders, warranty, recalls.
  • An agent only gets the tools of its own systems; calling another system is refused and written to audit_log.
  • Business rules live in the tools: a discount above your limit puts the deal on hold and sends an approval request to the right manager.

Act 3 · Inspect and enforce

The proxy stops being a pipe. It reads each conversation, decides how worried to be, and can end it.

Lesson 8

Sensitive topics: keywords and intent

Blocked session trace ↗
What it adds

Five topics, each detected three ways, at three levels: info warning block.

  • Topics: customer PII leak, discount fraud, competitor poaching, harassment, credential sharing.
  • Keyword rules (any:) catch the obvious; co-occurrence rules (all:, such as "my portal login" + "send") catch intent phrased innocently.
  • When a rule fires, a short LLM intent check can raise the level or dismiss a co-occurrence false alarm, never a keyword hit.
  • Three warnings on one topic in one session become a block. Every finding is a row in signals.
Code

proxy/firewall_topics.yaml, proxy/firewall.py · page docs/lessons/08-sensitive-topics.md

Lesson 9

The proxy firewall answers instead of the LLM

Blocked session trace ↗
What it adds

On a block, the proxy does not forward the request. It replies itself, in the exact shape of an LLM answer, saying the conversation was blocked under the acceptable-use policy, and the session stays closed.

  • Route firewall: never sent upstream, 0 tokens. Route firewall-response: the LLM's answer was withheld.
  • Every decision and every admin block, unblock or note goes to admin_actions; block state survives a restart.
  • Agents keep their own log in logs/agents/<id>.jsonl, so the trace shows both sides of the same answer.

Act 4 · Make it visible

Most of this happens where nobody can see it. The last two lessons turn the proxy log into something an administrator, or an audience, can read at a glance.

Lesson 7

The admin console

Admin console ↗
What it adds

VXC Motors, then department, person, session and conversation, with a written summary at every level and the firewall's alerts beside it. An administrator reads the summaries and only drills down where an alert says it is worth it.

  • Summaries are written by the LLM through the same proxy (exempt from the firewall) and cached by the last call id.
  • Alert rail filters by block, warning and info; clicking an alert opens its session.
  • Block, unblock and note buttons call the proxy and land in admin_actions.

Lesson 10

Mission control and replay

Mission control ↗
What it adds

Every agent is a node. Each LLM call travels agent → proxy → LLM and back, each tool call goes out to the system it touches, and a block flashes red at the proxy and on the agent.

  • Replay any window of the log at up to 900×, or go live against a running proxy.
  • Next alert › jumps straight to the next warning or block.
  • The page bakes a log snapshot in, so it runs anywhere without a server.

Your turn

Run it yourself

Repository ↗

Everything above is in the vxc-motors branch. Tests need no network; the console can show the committed day without spending a single request.

  • Start with docs/MASTER_PLAN.md, then one page per lesson in docs/lessons/.
  • Only the proxy needs OPENROUTER_API_KEY. Everything else talks to the proxy with a dummy key.
  • The full workday costs about 360 to 450 free requests and 25 to 60 minutes.
pip install -r requirements.txt
python3 -m unittest discover -s tests       # 50 tests, no network

# replay the committed day, no LLM requests
python3 console/server.py --db runs/2026-10-27/proxy.db
#   console  http://127.0.0.1:8090/
#   mission  http://127.0.0.1:8090/mission

# live: proxy, then a workday slice
export OPENROUTER_API_KEY=...
PROXY_LOGGING=on python3 proxy/proxy.py &
python3 -m runner.run --only maria-santos --until 09:10
python3 console/server.py
