Sheet 1 · what

Prax Analytics builds pipelines. Prax App builds single applications. Prax Systems builds things made of several cooperating parts, where the behaviour that matters happens between them: agents, a proxy, a firewall, local services, a console.

Sheet 7 · replicate

Copy the templates into a new folder, fill them in the order of the workflow, and let the checker tell you what is missing.

git clone https://github.com/<owner>/prax-systems
mkdir my-system && cp -r prax-systems/templates/* my-system/
mkdir -p my-system/tools && cp prax-systems/tools/prax_check.py my-system/tools/
cd my-system
python3 tools/prax_check.py . --level silver   # lists every gap until it passes
  1. R1No code without spec: new behaviour means a new or changed R-id.
  2. R2No R-id without proof: a test cites it, or its SPEC row names a manual demo step.
  3. R3No repo without rebuild prompts: P-01…, P-REBUILD and P-VERIFY.
  4. R4Clone and see: recorded demo data, one command, no secrets.
  5. R5Secrets stay out: keys in env vars, demo data scrubbed, explainer offline.
  6. R6Decisions are written down the day they are made, autonomous ones included.
  7. R7Contracts are versioned: breaking one means a new version id.

Level · first releaseSilver

LevelGold
