llm-proxy-log · explainer

Every LLM call your agents make, written down

A small proxy sits between your AI agents and the LLM provider. Agents change one setting, their base URL. The proxy keeps the only API key and records each call in one SQLite file.

One process in the middle

Agents talk to the proxy as if it were the provider. The proxy forwards each request with the real key, returns the answer unchanged, and writes one row to logs/proxy.db. A dashboard (or any other program) reads that file.

Without it, nobody can say who asked what

The key is everywhere

Every agent needs the provider key in its environment. Rotating it means touching every agent, and any one of them can leak it.

Totals, not conversations

The provider's dashboard shows spend per key. It cannot tell you that Omar's support bot spent 13 calls on one refund ticket last Tuesday.

Logging is everyone's job, so nobody's

Each agent would need its own logging, in its own format. The one you need is always the one that did not log.

Failures leave no trace

A 429 at 2 a.m., a model that stopped answering, a tool call with bad arguments. Without the exact request and response, you guess.

            "X-Agent-Dept": "research"}

Build your own variant

Another provider: set UPSTREAM_BASE_URL. More context per call: add any X-Agent-<Name> header and it lands in labels. Another company for the demo: edit demo/company.json and demo/scenarios.json. A new language: give a model GOAL.md, SPEC.md and the tests, and paste P-REBUILD from PROMPTS.md.

Built with Prax Systems: GOAL, SPEC, PROMPTS and tests ship with the code so the system can be rebuilt. Keys: Space play/pause, ← → step, 1–5 scenes.
