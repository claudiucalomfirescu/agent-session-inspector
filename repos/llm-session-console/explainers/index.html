llm-session-console · Prax Systems

From four weeks of agent traffic to the one message that crossed the line

An LLM proxy writes every conversation your agents have into a SQLite file. This console opens that file read-only and lets you drill down: all traffic, one user, one day, one session, one call, the firewall finding on it. Here is what it is, why it exists and how one real blocked message travels through it.

Scene 1 · What it is

A read-only window on the proxy's log

Agents talk to the LLM only through the proxy. The proxy logs each call. The console sits beside the log and never touches the agents, the proxy or the LLM.

Scene 2 · The problem

The log is complete and nearly unreadable

Every chat-completions request carries the whole conversation so far, plus the system prompt and the list of tools. So the log stores each message again on every turn, and a three-turn session of one sales agent already weighs 5,614 prompt tokens per call. Questions like "who used the LLM last week" or "what did the firewall stop on Tuesday" need SQL over JSON inside JSON.

Scene 4 · What you get

Charts for the big picture, a galaxy for the shape of it

The bars are the real calls per day in the bundled four-week log; red is calls the firewall blocked, amber warnings. Weekends are near zero, 14 Oct has an incident cluster, and the last two days are the recorded workdays. On the right, the 3D view's idea in miniature: users are stars, their sessions are planets, colour shows the worst firewall level.

Calls per day, 5–29 Oct 2026
  • All traffic: calls, sessions, users, tokens and firewall counts; a chart you can switch between calls, sessions, tokens, users and findings, by day or week; a weekday × hour heatmap.
  • A user: the same charts for one person, the tools the LLM called for them, and every session, filterable to warnings or blocks.
  • A session: the conversation step by step, tool calls with their arguments, firewall findings on the message they concern, and the raw JSON on demand.
  • Firewall: findings over time, a topic × level matrix, detectors and every admin action, each row opening the session at that call. Logs without a firewall just hide this layer.
Scene 5 · Replicate it

Run it in a minute, then point it at your own log

Python 3.10 or newer, nothing to install, no API key, no network. The demo logs ship compressed in the repo.

See the demo 
git clone <url> llm-session-console
cd llm-session-console
python3 -m console
# open http://127.0.0.1:8095/
Use your own proxy log 
python3 -m console --db /path/to/proxy.db
# the proxy can keep writing; new calls show on the next click
Build your own variant
  • Have your agents send X-Agent-User, X-Agent-Dept and X-Session-Id to the proxy. Without them, users fall back to the hashed API key, then the agent id.
  • Any SQLite file with a calls table of id and ts loads; every other column is used when present (SPEC.md §3).
  • Add a chart metric in console/store.py (series) and web/app.js; the galaxy only needs two endpoints.
  • Rebuild it in another language with PROMPTS.md → P-REBUILD, then check it with P-VERIFY and the tests.
